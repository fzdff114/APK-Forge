# MNN Chat 本地模型识别与离线转换设计

## 目标
在 MNN Chat Android APK 内完成常见本地模型的识别、导入和可行范围内的离线转换。保留目前已实现的 MNN 模型文件夹导入和 ADB 导入，不覆盖原版安装。

## 设计方案与取舍
1. **把官方 Python 转换脚本和全部依赖直接打进 APK**：最接近原始脚本，但依赖 NumPy、MNN Python 工具；Safetensors 路径还依赖 PyTorch。Android arm64 的依赖体积与可用性风险很高，不选作主实现。
2. **Android 原生转换层（JNI/NDK）**：在手机本地读取 GGUF/Safetensors 权重，复用/移植 MNN 的必要转换逻辑，并通过本地 MNN 转换能力生成标准模型目录。无需把模型上传云端；按模型架构逐步开放支持。**采用此方案**，但不把尚未移植的架构宣传为已支持。
3. **云端转换**：技术上更容易复用官方脚本，但不符合本次“手机本地完成”的要求，不采用。

## 用户流程
- 本地模型页保留“从文件管理器导入 MNN 模型文件夹”。
- 增加“导入模型文件”和“导入模型文件夹”入口。
- 单文件选择器用于 GGUF；文件夹选择器用于多分片 Safetensors/Hugging Face 模型目录或现成 MNN 目录。
- 先识别格式、模型架构、必要配置及模板是否齐全，再显示“直接导入 / 可转换 / 当前不支持”的明确状态。
- 转换在应用私有目录执行，展示进度与失败原因；原始模型不删除。
- 转换成功后校验产物结构与关键文件，再登记为本地模型；校验失败不得加入模型列表。

## 首批格式范围
| 输入 | 首批处理方式 |
|---|---|
| 已导出的 MNN 模型目录（根目录含 config.json） | 直接导入 |
| GGUF（.gguf） | 识别并尝试本机转换；必须有该架构匹配的 MNN 模型结构模板，且权重类型/架构受转换器支持 |
| Hugging Face Safetensors 文件夹（config.json、tokenizer 和一个或多个 .safetensors 分片） | 识别并尝试本机转换；必须有匹配的 MNN 结构模板及必要配置 |
| ZIP 模型包 | 安全解压到临时目录后识别内部结构；只导入有效 MNN 目录，不把 ZIP 本身当模型 |
| ONNX、TFLite、PyTorch .pt/.bin、单独的 .safetensors 文件及未知格式 | 识别并给出具体说明；首批不承诺可直接转换为 MNN 聊天模型 |

## 转换与验证约束
- 转换不依赖云端服务；无网络时仍可处理已具备的源模型和结构模板。
- 不能只改扩展名或伪造 config.json。转换必须真正读取权重并生成 MNN 模型数据。
- GGUF 和 Safetensors 的格式支持以实际移植并测试的架构、量化类型为准；不支持时应明确指出架构/权重类型或模板缺失。
- 官方 MNN 文档当前给出的 GGUF/Safetensors 工作流需要预先具备匹配模型的 MNN 结构文件（例如 llm.mnn、llm_config.json、tokenizer 文件及 config.json），再转换权重；这项前置条件要在 UI 中提示。
- 转换前检查可用存储空间；转换使用临时目录，成功并校验后再原子移动到模型库。
- 保留已有模型、ADB 路径和原始文件；同名模型自动避让，不覆盖。
- 第一版只以文本 LLM 为范围；官方文档指出这条 GGUF/Safetensors 权重转换路径不支持多模态转换，不能暗示支持图片/音频模型。

## 验收标准
1. MNN 目录、GGUF 文件、Safetensors 模型文件夹、ZIP 包、ONNX/TFLite/PT/未知文件均能被正确分类，不把格式识别误报成转换成功。
2. 有匹配模板且属于已实现架构/量化类型的 GGUF/Safetensors 测试样本，可离线转换并生成完整 MNN 模型目录。
3. 缺少模板、配置、磁盘空间或遇到不支持的架构/量化类型时，显示可理解原因，临时文件清理且源文件不受影响。
4. 原有 MNN 文件夹导入、ADB 导入及模型列表刷新仍正常。
5. APK 在 arm64 Android 上构建成功；转换器核心有自动化测试，至少覆盖格式识别、模板校验、转换成功/失败和输出校验。

## 明确不做
- 不上传用户模型或其权重到云端。
- 不把任意 ONNX/TFLite/PyTorch 文件承诺为可转成聊天 LLM。
- 不将未真正执行转换的原文件重命名为 .mnn。
- 不删除或覆盖用户原始模型。
